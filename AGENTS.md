# New Home Finder — agent guide

A personal-use PWA for finding US counties to move to: the user sets criteria and
weights, gets a ranked list and a choropleth map. No accounts, no backend, no DB.

## Read the master plan first

**`Working Master Plan.md` is the source of truth for what to build and in what order.**
Before implementing anything, read it — in particular:

- §2 *Core architectural decision* — this is an ETL problem; the browser does all scoring
  client-side over two static files. Server-side features are allowed since 2026-11-13
  (a Worker script on `/api/*`), but scoring stays in the browser.
- §5 *Phase 1 CSV schema* — the exact columns the ETL must produce; keep `fips` a string.
- §6 *Scoring model* — percentile normalization, direction flags, weighted score, hard
  filters, score decomposition. This is the product; everything else is plumbing.
- §8 *Stack* — MapLibre (not Mapbox), URL params for filter state, Python for ETL only.
- §9 *Build order* — **strictly sequential**. Work the earliest phase with unchecked
  items. Do not start the map before the scoring engine works.
- §10 *Explicitly deferred* — do not build these, even if asked in passing; point back
  to the plan instead.

The plan is a working document. When you finish a step, tick its checkbox. When the code
diverges from the plan, the code is right — update the plan (and its `Last updated` date)
rather than leaving it stale. Record new decisions or open questions there, not in chat.
Dated history goes in `docs/plan-changelog.md` (newest first), not in the plan.

## Project layout

- `src/app/` — Next.js App Router. `manifest.ts`, `sw.ts`, `~offline/` are the PWA pieces.
  Icons and the share image are file conventions there (`favicon.ico`, `icon.svg`,
  `apple-icon.png`, `opengraph-image.png`); sources and colors are in `brand/` (app name:
  Lodestar). The in-app logo is `src/components/ui/lodestar-logo.tsx`.
- `src/components/pwa-provider.tsx` — registers the service worker on the client.
- `serwist.config.mjs` — builds `public/sw.js` after `next build` (generated, git-ignored);
  `scripts/copy-sw-to-out.mjs` then copies it into `out/`.
- Hosting (plan §9 Phase 13): a Cloudflare Worker serving the static export in `out/`
  (Workers Static Assets, no Worker script). `wrangler.jsonc` is its config, `public/_headers`
  holds the response headers (a static export can't use `next.config.ts` `headers()`),
  `public/.assetsignore` keeps a locally built `data/tracts` out of a deploy, and the committed
  `.env.production` sets `NEXT_PUBLIC_DATA_URL`. Pushes to main deploy it
  (`.github/workflows/deploy.yml`). The apex-to-www redirect and "Always Use HTTPS" are
  Cloudflare dashboard settings. Vercel (`vercel.json`) is only the rollback until removed.
- `src/lib/scoring/` — the scoring engine (plan §6). Pure TS, no UI imports; tests beside it.
- `src/components/finder/` — the UI: filters modal, results list, place view, and
  `county-map.tsx` (MapLibre).
- Place search ("Find a place", plan §9 Phase 12): `src/lib/tracts/places.ts` builds the index
  from county names and the area labels in `areas.json`; `place-search.tsx` is the dialog and
  the looked-up place's list; the map draws the place from its counties' tract shapes
  (`place-shapes.ts`, the `lookup` layer in `county-map.tsx`). No new data file, no geocoder.
- `src/components/ui/` — generic pieces (`Modal`, `InfoTip`, `theme.ts`). Dark mode is `<html data-theme>`
  (use `dark:` as usual; never `prefers-color-scheme` directly). Type sizes and spacing are tokens
  in `globals.css` (`text-caption`/`label`/`body`/`title`/`heading`); don't use `text-[11px]`.
- `scripts/copy-maplibre-worker.mjs` — runs on `predev`/`prebuild`; copies MapLibre's web
  worker into `public/maplibre/` (generated, git-ignored). The map breaks without it.
- `public/data/counties.json` and `counties.topo.json` — the dataset and county shapes,
  **generated by the ETL**. Don't hand-edit; rebuild with `python -m etl.build`. Without the
  interim caches (a fresh clone), `python -m etl.patch <source…>` refreshes some sources'
  columns in the published file (zillow_county, newbuyer, nri, edges). Keep counties.json
  under 2 MB — the service worker won't precache it past that (a test checks).
- ETL pipeline (Python, `pandas`) lives in `etl/`, outside the app runtime — see plan §2/§8.
- Area data inside counties (plan §9 Phase 8, `etl/tracts/`) is **never in git**: production
  reads it from Cloudflare R2 (`data.lodestarmap.com`, `NEXT_PUBLIC_DATA_URL`), rebuilt monthly
  by `.github/workflows/tracts-refresh.yml`. `next dev` reads the same host (`.env.development`, committed);
  to use files you built yourself, set `NEXT_PUBLIC_DATA_URL=/data` in `.env.local`. Hand-downloaded sources (SEDA) live in a private
  R2 bucket: `python -m etl.inputs pull` after cloning. Don't commit data files under `etl/data/raw/`.
- Pollution (plan §9 Phase 11, `etl/pollution/`): measured at every 2020 census block where
  people live and population-weighted — never a county source or a neighbour's value. CI runs
  `python -m etl.pollution published` and `python -m etl.tracts.backfill --pollution` after
  publishing area files (a monthly rebuild without them drops the columns); counties.json
  needs `python -m etl.pollution all` then `python -m etl.patch pollution`. Pollution scores on
  fixed anchors, not percentiles (`src/lib/tracts/pollution.ts`); radon is shown, never ranked.
  A source that's down keeps the tables last published to R2 (`etl/pollution/carry.py`), and
  `tracts/pollution.json` dates each source for the area page.
- State laws: design and rules in `LAWS.md` — read §8 *The automation line* first. The table
  (`etl/data/law_definitions.csv` + `law_values.csv`) is written only by
  `python -m etl.laws.refresh`, which parses each cited source; never hand-edit values.
  The refresh runs monthly in `.github/workflows/laws-refresh.yml` and publishes
  `public/data/laws.json`, which the county card's "Laws & taxes" section reads.

## Data checks

`etl/data_checks.json` lists the sources a person has to refresh or re-check (year settings
bumped by hand, manual downloads, files publishers move), how often, and when they were last
checked; plus a regular review for better sources. A SessionStart hook (`.claude/settings.json`
→ `node scripts/data-checks.mjs --hook`) tells Claude at startup what's due, so it can tell
the user. `node scripts/data-checks.mjs` lists everything. After a check, run
`node scripts/data-checks.mjs done <id>` and commit the file. Add an entry for any new
source that needs a person.

## Commands

```bash
npm run dev        # next dev + service-worker watcher (SW disabled in dev)
npm run build      # next build (static export to out/) && serwist build, then copy sw.js into out/
npm run start      # serve out/ with `wrangler dev`; use this to test install/offline
npm run preview    # build, then wrangler dev
npm run deploy     # build, then wrangler deploy (the Worker)
npm run lint
npm run typecheck
npm test           # Vitest: scoring engine unit + real-data tests
```

Run `lint`, `typecheck`, `test`, and `build` before considering a change done.
For ETL changes, also run `etl/.venv/bin/python -m etl.test_offline`. For law changes, run
`etl/.venv/bin/python -m etl.laws.test_sources` and `-m etl.laws.test_verify`.

## Conventions

- TypeScript, App Router, Tailwind 4. Server Components by default; `"use client"` only
  where needed.
- Scoring logic is a pure TS module with unit tests — no UI imports (plan §9, Phase 2).
- The app is a
  Next.js static export (`output: "export"`), so route handlers, `headers()`/`redirects()`/
  `rewrites()` in `next.config.ts`, server actions, middleware/proxy and `next/image`
  optimization won't build. Response headers go in `public/_headers`.
  Anything that needs a server goes in a Worker script on `/api/*` (`wrangler.jsonc`), not in
  Next.js. The app keeps working offline; a feature that needs the server may be off or
  limited offline and should say so.
